# 逻辑工坊 · Logic Lab

一个中文经典逻辑工作台。通过按钮输入命题变量、量词、谓词与逻辑符号，填写前提和结论，检验论证是否有效，并展示自然演绎证明过程。命题逻辑保留真值表；一阶逻辑使用语法证明搜索，并在找到有限反例模型时给出中文解释。有效论证不加载模型；无效命题论证可授权按需下载本地小模型改写反例。

## 使用

- 点击前提或结论输入框，再点击左侧变量、个体词项、连接词或量词按钮；也支持直接键盘输入。
- 量词示例：`∀x (P(x) → Q(x))`、`∃x P(x)`、`∀x ∃y R(x, y)`。大写字母是谓词或命题；`x y z u v w` 是个体变量，其他小写字母是常项。
- 点击「验证论证」，或按 `Ctrl / ⌘ + Enter`。
- 有效论证不存在「所有前提为真、结论为假」的赋值；无效论证会显示具体反例。
- 命题论证保留可筛选、可导出 CSV 的真值表，并附加自然演绎证明。
- 一阶论证显示自然演绎证明：每一步列出公式、规则、依赖行号与子证明缩进；量词规则附带本征常项条件。
- 「命题含义」可为变量设置中文语句；修改含义不改变逻辑形式。
- 提供肯定前件、否定后件、假言三段论、二难推理、常见形式谬误，以及全称/存在量词推理与量词顺序谬误等示例。
- 输入自动保存在当前浏览器；不上传到服务器。

支持 `¬ ∧ ∨ → ↔ ⊕ ↑ ↓ ← ( ) ⊤ ⊥ ∀ ∃`。键盘别名包括 `! ~ && & || | -> => <-> <=> = ^ <- ⊻ ≢ ⊼ ⊽ ⊃ ≡ forall exists`。命题连接词优先级为 `¬ > ∧/↑ > ∨/⊕/↓ > →/← > ↔`；量词与 `¬` 同级，作用域默认为紧随其后的公式，复杂作用域请加括号。

## 判定方式与边界

- **命题逻辑**：穷举真值表仍是权威判定；最多 10 个不同命题变量、8 条前提，每条公式最多 500 个字符。有效论证同时给出自然演绎证明。
- **一阶逻辑（无函数、无等词）**：先做有界自然演绎证明搜索；找到证明即判有效。未找到证明时，再搜索小论域有限反例模型；找到“前提全真、结论为假”的模型即判无效。两者都没有时显示「尚未判定」，绝不把搜索失败说成无效。
- 自然演绎规则包括前提、假设、合取/析取/蕴涵/等价引入与消除、否定引入与消除、经典反证法、爆炸原理、全称引入/消除、存在引入/消除。证明返回前会经过独立规则校验。
- 有限反例模型默认搜索论域大小 1–3、原子谓词实例数与映射数有上限。它用于给出可核对的反例，不是完整的一阶逻辑判定过程。
- 这是经典逻辑工具，不支持函数项、等词、模态、高阶量词或无穷论域上的完备语义判定。有效性不意味着前提真实；矛盾前提导致的空真有效会单独提示。

## 本地运行

需要 Node.js 20 或更新版本。核心逻辑无第三方运行时依赖；可选本地模型的开发依赖只用于构建浏览器推理运行时。

```sh
npm ci --ignore-scripts
npm run dev
# 打开 http://localhost:3000
PORT=8080 npm run dev  # 自定义端口
```

## 检查

```sh
npm test
npm run check
```

33 项单元测试覆盖连接词语义、优先级、括号、键盘别名、语法错误、2,300 个随机公式的格式化往返、中文翻译、有效与无效论证、反例、空真有效、重言式、计算限制、量词解析与捕获避免替换、自然演绎证明及校验、有限反例模型，以及模型输入只来自无效反例。

## 按需本地小模型

- 模型：`onnx-community/Qwen2.5-0.5B-Instruct`，固定 revision `22942cb7d7ba4cc81bb4673549ca4d4614469b5e`，Apache-2.0。
- **不会随页面加载模型。** 只有论证无效、用户阅读下载说明并点击同意后，才创建推理 Worker、加载本地运行时及请求 Hugging Face 权重。
- WebGPU 可用时优先使用 `q4f16`（约 460 MiB）；否则使用 CPU `q4`（约 750 MiB），另需 tokenizer。WebGPU 初始化失败时可回退 CPU，并明确提示额外下载。
- 模型与 tokenizer 使用浏览器 Cache API 缓存；可停止/卸载、清除缓存。清除后只有再次授权才会下载。关闭页面会释放内存中的模型。
- `npm run build` 用 esbuild 将 Transformers.js 4.3.2 打入 `vendor/llm/worker.js`，并复制匹配的 ONNX Runtime WASM。`vendor/` 不提交 Git，不含权重。开发服务器启动前自动构建。
- 公式、变量含义和生成文本不发送到服务端；下载权重会暴露正常网络元数据（例如 IP）给权重托管方。没有云推理 API。
- 模型只改写程序已经验证的反例，不能改判有效性。确定性反例直译始终保留；模型失败、超时、离线或输出不可用时均可继续使用网站。
- “明显不合理”是解释**从前提硬推出结论的跳步**，不是虚构荒谬事实或断言结论现实中必假。小模型可能改写不准确，需与反例核对。

模型首次下载受网络和内存限制，建议桌面设备。自动化测试覆盖授权前的零模型请求、有效论证隐藏翻译、无效反例、Worker 客户端协议、取消与错误处理；另用微型 ONNX 测试模型验证了真实浏览器 WASM 运行时、模型会话创建和生成调用。沙箱无法访问权重托管方，因此真实 Qwen 权重的端到端推理尚未验证。

## 静态部署

先运行 `npm ci --ignore-scripts && npm run build`，再托管静态文件与生成的 `vendor/`。入口是 `index.html`，应用资源使用相对路径，不需要后端或密钥。推理运行时自托管；仅模型权重按需从 Hugging Face 下载。

GitHub Pages 工作流会构建运行时，并只上传 `_site/` 内的静态应用和运行时，不上传 `node_modules` 或模型权重。推送到 `main` 后会部署站点。也可在 GitHub Actions 中手动运行「Deploy static content to Pages」。由于使用 ES Modules，请通过 HTTP 访问，而不是双击以 `file://` 打开。

## 文件

- `index.html`：中文界面、符号面板、使用指南。
- `styles.css`：响应式布局与可访问性样式。
- `app.js`：输入与光标、论证编辑、翻译、真值表、保存与导出。
- `logic.js`：命题逻辑 tokenizer、递归下降解析器、求值器、翻译器和穷举有效性判定。
- `fol.js`：一阶逻辑语法树、量词作用域、格式化、替换与翻译。
- `natural-deduction.js`：有界自然演绎证明搜索、规则校验与证明文本。
- `countermodel.js`：有界有限反例模型搜索。
- `argument.js`：命题/一阶统一分析入口。
- `server.mjs`：零依赖本地静态服务器。
- `explanation.js`：无效论证的确定性反例叙述。
- `llm-client.js`、`src/llm-worker.js`：授权后懒加载的本地推理及取消逻辑。
- `scripts/build.mjs`：构建自托管推理运行时。
- `tests/`：Node.js 原生测试。

公式通过明确的语法树解析，不使用 `eval` 或 `new Function`；用户输入在渲染时进行 HTML 转义。
