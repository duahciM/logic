# 逻辑工坊 · Logic Lab

一个中文经典逻辑工作台。通过按钮输入命题变量、量词、谓词、定义符号与等词，填写前提和结论，检验论证是否有效，并展示自然演绎证明过程。命题逻辑保留真值表；一阶逻辑使用语法证明搜索，并在找到有限反例模型时给出中文解释。默认不会加载模型；可授权按需下载本地小模型，或配置外部 API 通道。除了改写已验证反例，还可把完整前提和结论交给 LLM 自主解释，并复核它提出的候选反例。

## 使用

- 点击前提或结论输入框，再点击左侧变量、个体词项、连接词或量词按钮；也支持直接键盘输入。
- 量词示例：`∀x (P(x) → Q(x))`、`∃x P(x)`、`∀x ∃y R(x, y)`。大写字母是谓词或命题；`x y z u v w` 是个体变量，其他小写字母是常项。
- 定义与等词示例：`P ≝ Q ∧ R`、`a = b`、`a ≠ b`、`∀x (x = a → P(x))`。`≝`（别名 `≔`、`≜`、`:=`、`=def`、`=df`）按双向等价处理；`=`/`==` 与 `≠`/`!=`/`/=` 只比较个体项。
- 点击「验证论证」，或按 `Ctrl / ⌘ + Enter`。
- 有效论证不存在「所有前提为真、结论为假」的赋值；无效论证会显示具体反例。
- 命题论证保留可筛选、可导出 CSV 的真值表，并附加自然演绎证明。
- 一阶论证显示自然演绎证明：每一步列出公式、规则、依赖行号与子证明缩进；量词规则附带本征常项条件。
- 「命题含义」可为变量设置中文语句；修改含义不改变逻辑形式。
- 提供肯定前件、否定后件、假言三段论、二难推理、常见形式谬误，以及全称/存在量词推理与量词顺序谬误等示例。
- 输入自动保存在当前浏览器；默认不上传到服务器。只有启用外部 API 并确认发送后，当前反例或完整论证才会发送到所配接口。

支持 `¬ ∧ ∨ → ↔ ⊕ ↑ ↓ ← ( ) ⊤ ⊥ ∀ ∃ ≝ ≔ = ≠`。键盘别名包括 `! ~ && & || | -> => <-> <=> ^ <- ⊻ ≢ ⊼ ⊽ ⊃ ≡ forall exists := =def =df == != /=`。命题连接词优先级为 `¬ > ∧/↑ > ∨/⊕/↓ > →/← > ↔/≝`；相等/不相等是原子公式，量词与 `¬` 同级，作用域默认为紧随其后的公式，复杂作用域请加括号。公式等价请用 `↔`、`≡` 或 `<->`；`=` 现在表示个体项相等，不再作为 `↔` 的别名。

## 判定方式与边界

- **命题逻辑**：穷举真值表仍是权威判定；最多 10 个不同命题变量、8 条前提，每条公式最多 500 个字符。有效论证同时给出自然演绎证明。
- **一阶逻辑（含等词、无函数）**：先做有界自然演绎证明搜索；找到证明即判有效。未找到证明时，再搜索小论域有限反例模型；找到“前提全真、结论为假”的模型即判无效。两者都没有时显示「尚未判定」，绝不把搜索失败说成无效。
- 自然演绎规则包括前提、假设、合取/析取/蕴涵/等价/定义引入与消除、否定引入与消除、经典反证法、爆炸原理、全称引入/消除、存在引入/消除，以及等词自反 `=I` 与替换 `=E`。证明返回前会经过独立规则校验；等词替换会检查自由出现与变量捕获。
- 有限反例模型默认搜索论域大小 1–3、原子谓词实例数与映射数有上限。它用于给出可核对的反例，不是完整的一阶逻辑判定过程。
- 这是经典逻辑工具，不支持函数项、模态、高阶量词或无穷论域上的完备语义判定。定义符号不执行赋值或全局定义注册，只作为当前论证中的双向等价公式。有效性不意味着前提真实；矛盾前提导致的空真有效会单独提示。

## 本地运行

需要 Node.js 20 或更新版本。核心逻辑无第三方运行时依赖；可选本地模型的开发依赖只用于构建浏览器推理运行时。

```sh
npm ci --ignore-scripts
npm run dev
# 打开 http://localhost:3000
PORT=8080 npm run dev  # 自定义端口
```

## 按需本地小模型

- 模型：`onnx-community/Qwen2.5-0.5B-Instruct`，固定 revision `22942cb7d7ba4cc81bb4673549ca4d4614469b5e`，Apache-2.0。
- **不会随页面加载模型。** 只有用户阅读下载说明并点击同意后，才创建推理 Worker、加载本地运行时及请求 Hugging Face 权重。反例改写模式仍只处理已验证无效论证；完整论证模式可解释有效、无效或尚未判定的论证。
- WebGPU 可用时优先使用 `q4f16`（约 460 MiB）；否则使用 CPU `q4`（约 750 MiB），另需 tokenizer。WebGPU 初始化失败时可回退 CPU，并明确提示额外下载。
- 模型与 tokenizer 使用浏览器 Cache API 缓存；可停止/卸载、清除缓存。清除后只有再次授权才会下载。关闭页面会释放内存中的模型。
- `npm run build` 用 esbuild 将 Transformers.js 4.3.2 打入 `vendor/llm/worker.js`，并复制匹配的 ONNX Runtime WASM。`vendor/` 不提交 Git，不含权重。开发服务器启动前自动构建。
- 本地通道不发送公式、变量含义和生成文本到服务端；下载权重会暴露正常网络元数据（例如 IP）给权重托管方。外部 API 通道见下节，默认关闭。
- 反例改写模式只改写程序已经验证的反例。完整论证模式允许模型自行组织解释并提出候选反例，但候选必须由程序逐条求值；模型文字不能改判有效性。确定性反例直译始终保留；模型失败、超时、离线或输出不可用时均可继续使用网站。
- “明显不合理”是解释**从前提硬推出结论的跳步**，不是虚构荒谬事实或断言结论现实中必假。小模型可能改写不准确，需与反例核对。

模型首次下载受网络和内存限制，建议桌面设备。自动化测试覆盖授权前的零模型请求、有效论证隐藏翻译、无效反例、Worker 客户端协议、取消与错误处理；另用微型 ONNX 测试模型验证了真实浏览器 WASM 运行时、模型会话创建和生成调用。沙箱无法访问权重托管方，因此真实 Qwen 权重的端到端推理尚未验证。

## 可选外部 API 通道

在“LLM 解释”面板中，把翻译通道切换为“外部 API（OpenAI 兼容）”，点击“配置 API”。支持自定义地址，也提供 OpenAI、DeepSeek、OpenRouter 预设；预设只是可编辑的默认值。

- 接口：OpenAI 兼容的 `POST /chat/completions`。地址填写到 `/v1`，或完整的 `/chat/completions`；必须使用 HTTPS，不能把密钥写进 URL。
- 配置项：API 地址、模型名称、可选 API Key。地址/服务商/模型可选择记住；**密钥只保存在当前页面内存，不写入 localStorage/sessionStorage，也不进入请求体或 URL**。
- 发送时机：保存配置不会发送请求。反例改写模式点击“发送反例并改写”；完整论证模式点击“发送论证，让 LLM 解释”。两者都需要确认；完整论证模式在论证内容变化后会重新确认。不会自动批量发送。
- 发送内容：反例改写模式发送当前公式的自然语言翻译、变量含义、反例赋值或有限模型解释；完整论证模式发送全部符号前提、结论、符号签名、可选含义提示和本地参考判定。不会发送其他论证、完整真值表、证明搜索内部状态或浏览器存储内容。
- 适用范围：反例改写模式支持命题无效反例和一阶有限反例模型；完整论证模式支持命题与一阶论证，并可复核模型提出的赋值或有限模型。本地小模型也可自主解释，但结构化输出能力有限，建议优先使用 API。
- 安全与兼容：请求使用 `Authorization: Bearer`（若填写密钥）、`credentials: omit`、`redirect: error`、`referrerPolicy: no-referrer`。浏览器直连需要服务端允许 CORS；失败、超时、401/403/404/429 或空输出都会保留上方确定性反例直译。
- 费用与隐私：请求可能产生费用，并受服务商隐私政策约束。API 输出只作辅助，不能改判有效性；请以上方真值表、证明或反例模型为准。

## 完整论证 · LLM 自主解释

在“LLM 解释”面板把解释模式切换为“完整论证 · LLM 自主解释”。网站会把当前论证的全部符号前提、结论、符号签名和可选含义提示打包发送给所选通道；发送前可展开“查看将发送的完整论证”。模型自行决定怎样解释，并尝试构造“前提全真、结论为假”的候选反例。

- 模型输出建议为 JSON：`explanation` 是中文解释，`counterexample` 是命题赋值或一阶有限模型；普通文字也会显示，但不会被当作证明。
- 程序会独立复核候选：命题赋值必须覆盖全部变量；有限模型必须覆盖常项、自由变量和谓词，论域限制为 1–4 个对象，等词按同一对象处理。
- 只有候选逐条求值后确实满足“全部前提真、结论假”，才显示“反例复核成立 · 论证无效”。一阶论证原本尚未判定时，复核成立的候选可补充为确定性反例模型。
- 候选不成立、格式不完整或没有候选时，会明确提示，不会把模型自称当作无效性证明；本地引擎原有判定不会被模型文字覆盖。
- “不合理”指从前提硬推结论的跳步，不是断言反例情景或结论在现实中荒谬。

## 静态部署

先运行 `npm ci --ignore-scripts && npm run build`，再托管静态文件与生成的 `vendor/`。入口是 `index.html`，应用资源使用相对路径，不需要后端或站点密钥。本地推理运行时自托管；模型权重按需从 Hugging Face 下载。外部 API 通道由用户自行配置，站点不保存用户密钥。

GitHub Pages 工作流会构建运行时，并只上传 `_site/` 内的静态应用和运行时，不上传 `node_modules` 或模型权重。推送到 `main` 后会部署站点。也可在 GitHub Actions 中手动运行「Deploy static content to Pages」。由于使用 ES Modules，请通过 HTTP 访问，而不是双击以 `file://` 打开。

## 文件

- `index.html`：中文界面、符号面板、使用指南。
- `styles.css`：响应式布局与可访问性样式。
- `app.js`：输入与光标、论证编辑、翻译、真值表、保存与导出。
- `logic.js`：命题逻辑 tokenizer、递归下降解析器、求值器、翻译器和穷举有效性判定。
- `fol.js`：一阶逻辑语法树、量词作用域、定义/等词、格式化、替换与翻译。
- `natural-deduction.js`：有界自然演绎证明搜索、规则校验与证明文本。
- `countermodel.js`：有界有限反例模型搜索。
- `argument.js`：命题/一阶统一分析入口。
- `server.mjs`：零依赖本地静态服务器。
- `explanation.js`：无效论证的确定性反例叙述。
- `llm-client.js`、`src/llm-worker.js`：授权后懒加载的本地推理及取消逻辑。
- `api-client.js`：可选 OpenAI 兼容 API 通道、配置校验、取消与错误处理。
- `llm-prompt.js`：本地/API 共享的反例改写与完整论证提示词、模式守卫。
- `llm-argument.js`：完整论证打包、模型响应解析、候选赋值/有限模型的独立复核。
- `scripts/build.mjs`：构建自托管推理运行时。
- `tests/`：Node.js 原生测试。

公式通过明确的语法树解析，不使用 `eval` 或 `new Function`；用户输入在渲染时进行 HTML 转义。
